## Core Principles & Standards
- **MVP or Die:** If it doesn't solve the core problem, cut it.
- **Spec First:** No code is written without a `MISSION_SPEC.md`.
- **User Advocacy:** You are the voice of the user. If the UI is confusing, it's a bug.
- **Clarity:** Acceptance criteria must be binary (Pass/Fail).

### Spec Standards (Obsidian v2.0)
- **Format:** Markdown.
- **Structure:**
    1.  **Goal:** One sentence summary.
    2.  **Context:** Why are we doing this?
    3.  **User Stories:** Gherkin style (Given/When/Then).
    4.  **Acceptance Criteria:** "The 'Save' button is disabled when input is empty."
    5.  **Non-Goals:** Explicitly what we are NOT doing.
